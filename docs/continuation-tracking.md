## Chaîne des copies candidates

Le [pilote Continuation](../scripts/continuation-tracking-run.mjs) réutilise les mécanismes généralisés et conservés du lot Completion. Il exige les chemins de base, de sélection, de périmètre et de sortie explicitement ; les sorties doivent porter un composant `continuation-`. Il ne réemploie aucun plan historique par défaut.

1. Recevoir les propositions des auteurs avec l’identifiant existant, le critère exact, ses clauses couvertes, ses limites, les fichiers et les preuves réellement exécutées. Un critère incomplet reste ouvert.
2. Geler une sélection JSON et une liste explicite des sources `src/` concernées, puis composer le plan avec `plan --baseline ... --proposal ... --select-file ... --feature-paths-file ... --archive-dir ... --output ...`. Toute dépendance d’un nouveau Validé doit être Validé dans la base ou dans ce même plan explicite.
3. Composer les natifs frais, les parcours publics DEV et les images réellement ouvertes avec `gates --stage development ...`. Les empreintes doivent correspondre aux sources gelées ; les outils ne créent pas d’attestation d’ouverture. Une carte SHA complète et la base Git suffisent à identifier les sources des nouvelles preuves ; les exécutions ne doivent pas copier des milliers de fichiers.
4. Créer les deux copies privées avec `candidate ...`. Le catalogue conserve chaque ancienne fiche Validé intacte, les critères, identités, dépendances, sources, périodes et statuts d’assets. Les notes sont complétées à la suite des réserves historiques.
5. Contrôler le JSON et chaque cellule/XML du XLSX avec `verify ...`. Le vérificateur Python indépendant lit les octets de la base Git et les parties ZIP ; il vérifie aussi les tableaux, formules, styles, validations, règles conditionnelles et caches des compteurs.
6. Importer le candidat et rendre les panneaux concernés avec `render ...`. Le compteur est modifié puis restauré en mémoire, sans export. Chaque panneau doit être réellement ouvert et revu avant `workbook-review ...`.
7. Après tous ces contrôles, `publish ... --publish` copie uniquement le JSON et le XLSX principaux et les revérifie. Ce contrôle de copie locale ne prétend ni compiler ni tester la distribution. Il restaure les deux originaux si la vérification échoue.
8. Reconstruire le registre, compiler, refaire les parcours de production, ouvrir leurs nouvelles captures et recomposer les preuves avec `gates --stage production ...`. Les fichiers `dist/` et l’absence de requêtes vers les sources DEV doivent être contrôlés. La livraison Git attend ces preuves et le contrôle final de préservation.

Les commandes acceptent les paramètres des scripts Completion correspondants ; le pilote exige explicitement les paramètres qui pourraient sinon reprendre une ancienne base. Le rendu demande `CODEX_PRIMARY_RUNTIME_NODE_MODULES` et `@oai/artifact-tool`. Il utilise SpreadsheetFile et ne prétend pas lancer Microsoft Excel ou Windows.
